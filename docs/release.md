# Release checklist

## Desktop (electron-builder, `apps/desktop/electron-builder.yml`)

- Windows: `npm run package:win` (repo root) fetches the datasets, builds the level packs and produces `apps/desktop/release/Mocchi-Setup-<version>.exe` (assisted NSIS installer, per-user, ~127 MB). For a signed build set `CSC_LINK` and `CSC_KEY_PASSWORD` (an EV/OV code-signing certificate) in the environment; unsigned builds trigger SmartScreen warnings.
- macOS (must run on a Mac): `npm run package:mac -w @jc/desktop`. Requires an Apple Developer ID certificate in the keychain and, for notarisation, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`. Hardened runtime is enabled.
- Linux: `npm run package:linux -w @jc/desktop` (AppImage).
- "Start with my computer" is applied only in packaged builds.

## JLPT level packs (must be published before the installer can download N4–N1)

- The installer ships N5 and `manifest.json`; N4–N1 are downloaded from `https://github.com/7tps/mocchi/releases/download/content-<CONTENT_PACK_VERSION>/` (constant in `packages/japanese-content/src/packs.ts`). `content-2026.10.1` is published. If a release is ever missing or unreachable, setup reports that the content couldn't be downloaded and the app retries on each start (Settings › Study content › Try again).
- Publish (from the repo root, after `npm run content:build`):
  `gh release create content-2026.10.1 dist/content/jlpt-n4.json.gz dist/content/jlpt-n3.json.gz dist/content/jlpt-n2.json.gz dist/content/jlpt-n1.json.gz dist/content/manifest.json dist/content/ATTRIBUTION.txt --repo 7tps/mocchi --title "Content packs 2026.10.1"`
- The app accepts a pack only if its SHA-256 matches the manifest bundled in the build, so a release's packs must come from the same `content:build` as the installer. Changing pack contents → bump `CONTENT_PACK_VERSION`, rebuild, publish a new release, rebuild the installer.
- Self-hosting: set `MOCCHI_CONTENT_URL` when running `content:build`/`package:win` (HTTPS required at runtime, except 127.0.0.1/localhost).
- Silent install: `/S /LEVEL=N5|N4|N3|N2|N1` (default: previous choice, else N5). The choice is stored in `HKCUSoftwareMocchiContentLevel` and `resourcescontentselection.json`; uninstall removes both (packs the app downloaded later stay in `%APPDATA%Mocchicontent` with the rest of the app data).

## Mobile (Expo)

- Development build: `npx expo run:android` / `npx expo run:ios` inside `apps/mobile` (Android Studio + JDK 17; Xcode on macOS).
- Store builds: EAS Build (`eas build -p android|ios`) or the native projects generated by `npx expo prebuild`. You need a Play Console account and an Apple Developer Program membership.
- Android 13+ asks for `POST_NOTIFICATIONS` at runtime (the app asks during onboarding after explaining why). Exact timing is not guaranteed under Doze/battery saver; reminders are best-effort by design.
- iOS limits pending local notifications to 64; the planner caps at 40.

## Device test plan (not yet executed — no SDKs on the build machine)

1. Fresh install → onboarding → allow notifications → placement exam → results persist after force-quit.
2. Deny notifications → app explains and links to settings; sessions still work from Home.
3. Change reminder times / quiet hours → "Upcoming" list updates; old reminders do not fire.
4. Tap a reminder (app killed, backgrounded, foregrounded) → a session opens.
5. Airplane mode → complete sessions → re-enable network → sync uploads; second device shows the same queue.
6. Type answers with the Japanese keyboard (kana and kanji conversion) and with romaji.
7. Change the device timezone → due items stay due at the same instants; streak follows local days.

## Sync server

`npm run api` (or `node --env-file=.env --import tsx src/main.ts` in `services/api`). Bind to `127.0.0.1` and terminate TLS in a reverse proxy (Caddy, nginx) when exposing it. Back up the `DB_PATH` file.
